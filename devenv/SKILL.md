# devenv — the developer-environment tool

`pnpm run devenv <action> [flags]`, from any directory inside the repository. Agents use the
**flag form only**: every menu question has a flag; in a non-TTY shell a missing flag makes the
tool exit non-zero **naming the flag** — it never hangs. `--help` prints the full usage.

## Mental model (read once)

- **Main checkout** = the repository's primary clone. It never gets an environment of its own;
  `up` there starts the *shared local stack* of the committed `supabase/config.toml`, `down`
  there stops it (never deletes it).
- **Extra worktree** = a git worktree made by `devenv create <name>` under the worktrees
  directory (`<worktrees dir>/<repo>-<name>`). Its **environment is named after it** — the git
  branch when that is lowercase letters/digits/dashes, else the directory minus the `<repo>-`
  prefix. One name = directory = branch = environment. `up` there never asks for a name.
- **Environment** = either a **cloud branch** (a Supabase preview branch `<devname>-<name>` off
  the dev parent project; bills ~$0.32/day while it exists) or a **local stack** (`--local`: a
  Supabase CLI stack of the worktree's own, `project_id <project>-<name>`, on a shifted port
  block; free, offline, needs Docker).
- `up` writes the worktree's `apps/backend/config/.env`, `apps/backend/config/.env.test` and
  `apps/frontend/.env` — generated, gitignored, headed `# generated by devenv up`. **Never
  hand-edit them**; personal secrets go in the per-machine base env
  (`~/.config/devenv/<project>/base.env`), test pins in the committed `.env.test.example`, then
  re-run `up`.
- **The test suites run against the worktree's environment** (the generated `.env.test` carries
  its credentials and a test port of the worktree's own, so two worktrees can run
  `test:integration` at once) **and wipe it** — re-run `grants` afterwards. In the main checkout
  the harness creates `.env.test` from the example (localhost pins) when it is missing.
- Ownership: an environment whose `<devname>-` prefix is not yours is only touched with
  `--not-mine`. **`--yes` never implies `--not-mine`.**
- Prod and staging are never a target; the tool refuses any parent that is not the dev project.
- The app's settings are data in `apps/backend/config/devenv.json` (project, dev parent ref,
  required base-env keys, next steps) plus a grants module it names (the capabilities). When that
  file declares a secret the base env lacks, `up` without a terminal exits 1 with
  `missing required base-env keys: <keys> — run \`devenv setup\` in a terminal`: **stop and ask the
  human** to run `pnpm run devenv setup` (or `up`) in a terminal — never write a value yourself.

## Actions

| Action | What it does | Flags |
|---|---|---|
| `setup` | Guided first run: Supabase PAT → `~/.supabase/access-token`, dev name, base env, editor check, worktrees directory | `--dev-name <n>`, `--base-env-from <path>`, `--worktrees-dir <path>`, `--skip-token`, `--skip-base-env` |
| `whoami` | Dev name, project, parent ref, token source, worktrees dir | — |
| `list` | Environments under the dev parent + local stacks: name, kind, owner, status, age, worktree | `--mine`, `--json` |
| `create <name>` | New worktree (branch `<name>` from `--from` or this checkout's HEAD), `pnpm install`, then `up` inside it | `--local`, `--from <ref>`, `--reuse-branch` (existing branch with no worktree), `--dir <path>`, `--size <s>`, `--force` (dirty checkout), `--dry-run` |
| `up` | Bring up this worktree's environment (cloud branch, or `--local`) and write its three env files (backend `.env`, `.env.test` on the worktree's test port, frontend `.env`); re-run to resume/regenerate | `--local`, `--name <n>` (override only), `--size <s>`, `--dry-run` |
| `down [name]` | Cloud: `--pause` (keep data, stop billing) or `--delete`. Local: stop (default) or `--delete` (drops volumes + workdir). Clears the owning worktree's `.env` target block and deletes its generated `.env.test` | `--pause` \| `--delete`, `--yes`, `--not-mine`, `--remove-worktree`, `--keep-branch`, `--force`, `--dry-run` |
| `sweep` | Offer to reclaim **your** environments whose worktree is gone (never others'; never on a timer) | `--yes` + `--pause` \| `--delete` (orphans only), `--dry-run` |
| `grants` | Grant/revoke capabilities on an Auth user: plan → confirm → apply → report (value · store · mechanism per line) | `--user <email>`, `--create-user`, `--capability <ids>`, `--revoke <ids>`, `--list`, `--dry-run`, `--yes` |
| `mcp <supabase\|postgres>` | Launch an MCP server pointed at *this* worktree's environment (editor use) | `--check` (print the target, no server) |

`--remove-worktree` also deletes the git branch when it has no commits beyond the main
checkout's branch (`git branch -d`); an unmerged branch is kept unless `--force`; `--keep-branch`
keeps it regardless. `create <name>` on an existing branch that has no worktree needs
`--reuse-branch`; on a branch some worktree already has, it refuses and names the worktree.

## Recipes

```bash
# Is the tool set up? (exit 0 + dev name/token source)
pnpm run devenv whoami

# Preview, then create an isolated LOCAL environment from staging (run in the main checkout)
pnpm run devenv create feat-x --local --dry-run
pnpm run devenv create feat-x --local            # then cd <worktrees dir>/<repo>-feat-x

# Same, but a cloud branch started from main
pnpm run devenv create feat-y --from main

# Inside the worktree: (re)start it / regenerate .env after a base-env change
pnpm run devenv up            # or: pnpm run devenv up --local

# What exists? (machine-readable)
pnpm run devenv list --json

# Grant capabilities to the seeded dev user (see the app's catalogue first)
pnpm run devenv grants --list
pnpm run devenv grants --create-user --capability regulations-admin,shape-designer --dry-run
pnpm run devenv grants --user test.user@acme.corp --capability regulations-admin,shape-designer --yes

# Tear down: environment, worktree and (merged) branch — run from the MAIN checkout
pnpm run devenv down feat-x --delete --remove-worktree --dry-run
pnpm run devenv down feat-x --delete --remove-worktree --yes

# Someone else's leftover branch (only when asked to)
pnpm run devenv down alice-old --pause --not-mine --yes

# Clean up my orphans (worktree gone, environment still there)
pnpm run devenv sweep --dry-run
```

Always `--dry-run` first for anything that creates, deletes, or costs money; the plan names the
worktree path, ports, branch/ref, and every file it would write.

## Where things live

| What | Path |
|---|---|
| Dev name, worktrees dir | `~/.config/devenv/config.json`, `~/.config/devenv/<project>/config.json` |
| Base env (personal secrets, mode 0600) | `~/.config/devenv/<project>/base.env` |
| Registry of environments | `~/.config/devenv/<project>/environments.json` |
| Supabase token (PAT, mode 0600) | `~/.supabase/access-token` (`SUPABASE_ACCESS_TOKEN` overrides) |
| Local stack workdir (gitignored) | `apps/backend/.devenv/<name>/supabase/config.toml` |
| Generated env files (gitignored) | `apps/backend/config/.env`, `apps/backend/config/.env.test`, `apps/frontend/.env` |
| The app's devenv settings (committed) | `apps/backend/config/devenv.json` + the grants module its `grants.module` names |

## Do not

- Run `up` in the main checkout expecting a private environment — it starts the shared stack.
- `--delete` the main environment (refused), or point anything at prod/staging refs.
- Edit a generated `.env`; change the base env or the committed `.env.example` and re-run `up`.
- Pass `--yes` and assume it covers `--not-mine` or `--force` — each is explicit on purpose.
- Read the full docs for routine use; this file is enough. For the why and edge cases:
  the app's runbook (`docs/reference/dev-environments.md` in aquatic-app — sections
  *Concepts*, *Quickstart*, *A worktree with its own …*, *Ending an environment*, *Granting roles
  and flags*) and the template README section "The `devenv` tool".
